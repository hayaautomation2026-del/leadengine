# Conversation handling: Phase 1

Implemented a side-effect-free conversation decision engine and a preview adapter
for the existing SDR model provider. It produces drafts and explicit wait, stop,
handoff and ignore decisions. It does not send messages or access Supabase.

- Keeps need, budget, timing and purchasing authority with source-message quotes.
- Answers price/details questions using owner-approved copy only.
- Asks one qualification question at a time; caps repeated questions and turns.
- Supports human takeover and return to SDR; stop requests cannot be restarted.
- Handles objections, requests to wait, duplicate messages, pauses and malformed
  model output. State can be serialized by the future persistence adapter.
- Records payment as unverified. Handoff requires checking offer fit; extracted
  facts alone are not proof of a suitable budget, booked appointment or sale.

The dashboard's new **SDR, keep handling it** button plays examples generated by
`demo_conversations.py` from the same decision engine. Both prospect messages and
AI readings are scripted fixtures. It includes a buyer who provides qualification
details and another who objects and asks to wait. Progress persists in the browser;
reopening pauses unfinished conversations. The public dashboard remains offline.

## Before Phase 2

A bounded owner-inbox test now uses the engine through a separate worker; see INBOX_CONVERSATION_TEST.md. General prospect reply handling remains unchanged. `preview_conversation_reply` is
not called from `main()` and the browser buttons do not control the real worker.
There are no new schema changes or live settings changes in this phase.

Next wire authenticated owner controls and durable per-thread state, preserve
Gmail reply threading, claim messages atomically, enforce send limits and stop
gates immediately before sending, and reconcile send-success/database-failure
before retrying. Deferred natural-language timing currently requires scheduling;
there is no automatic timed conversation resumption yet. Test against controlled
inboxes before enabling a limited prospect batch.

Mock tests establish decision logic, not model extraction accuracy, inbox
placement, scraping reliability or sales conversion. Evaluate the real model on
representative emails and quoted threads, including prompt-injection attempts,
before allowing autonomous replies. Approved offer/price terms are still required.

The DOM interaction test (`test_conversation_dashboard.cjs`, with jsdom 30.0.1)
checks start, both outcomes, pause/resume, takeover/return, reload pause, reset,
old saved-state recovery and the offline policy. Full-browser visual verification
was unavailable locally because the Chromium download failed.
